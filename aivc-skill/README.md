# AIVC：把虚拟干预分析做成清楚、可复查的流程

面向刚接触虚拟细胞的研究者，用自己的数据开展虚拟基因敲除、过表达或药物响应分析。Skill 帮助检查输入、选择适配路线、执行已有模型、整理结果和说明局限。

**本目录是基于 [Pengzhi-Gao/aivc-skill](https://github.com/Pengzhi-Gao/aivc-skill) 固定版本的改进版。** 上游来源见 [NOTICE](NOTICE)，原 MIT 许可见 [LICENSE](LICENSE)。这里提供流程和适配代码，模型环境、权重、先验和真实分析数据需要另外准备。

## 先选择你现在要做什么

首次获取源码后，先看 [如何让 Agent 读取完整 Skill](references/first-run.md#让-agent-读取完整-skill)。本页命令在 `aivc-skill/` 子目录执行；解压分发包时则在包含 `SKILL.md` 的 `aivc/` 目录执行。

| 你的目标 | 从哪里开始 | 会得到什么 |
| --- | --- | --- |
| 先了解结果长什么样 | 阅读 [历史肺癌报告](examples/lung_cancer/reports/reproduction-report.md) 和 [结果阅读顺序](references/first-run.md) | 理解历史图表和局限；图片通过固定上游链接联网查看，完整原始结果未随包提供 |
| 用自己的数据做 KO / OE | [首次分析指南](references/first-run.md) → [参数化示例](examples/ko_oe/README.md) | CellOracle 的模拟表达变化/状态位移，或 Geneformer 的表征影响 |
| 做虚拟药物响应/药筛 | 先明确用户基线还是模型自带对照，再读 [能力与实现程度](references/model-capabilities.md) 和 [模型配置](references/model-setup.md) | 后端实际支持的逐条件响应、可解释评分、质量记录及适用的排序 |
| 只复核已有结果或补图 | 给出已有运行目录和需要检查的问题 | 复核/重绘现有产物，保留来源，不自动启动新模型分析 |

若另行安装了虚拟细胞工作台，也可打开它附带的历史样例。本 Skill 包可以独立阅读和使用，不包含桌面工作台、真实数据或模型权重。

## 新手可以直接这样说

> 请使用这个 AIVC skill。我的单细胞数据是「完整路径」，想分别分析 STAT3 和 JUN 的虚拟敲除。我还不熟悉模型，请先检查数据、说明能回答什么问题，推荐与输入匹配的路线。只询问无法从文件和当前环境确定的必要信息，保留完整结果和验证状态。

> 我已经有一份运行结果，请先帮我解释执行状态、响应检查、排名状态和独立验证，再带我阅读主要图表；缺失的证据请直接指出。

> 我想用「基线文件」和「药物库文件」预测药物转录响应。「疾病参照文件」用于描述性方向比较。请先说明基线来源、权重适用范围和评分前提，先用小批条件检查输出，质量满足要求后再继续已授权的完整范围。

不要求你一开始就知道解释器路径、全部模型名或每个技术参数。Agent 先检查已提供信息，给出有依据的设置；会改变研究问题的缺项，例如联合还是分别扰动、OE 目标水平、是否采用模型自带基线，需要明确。

## 一次分析的实际步骤

1. **明确问题。** 选择 KO、OE 或药物响应；说明目标基因、药物候选或待复核目录。
2. **检查输入和环境。** 确认数据格式、矩阵层和尺度、基因 ID、物种、背景与必需资源。生成检查记录，列明阻断项和未检查项。
3. **确定路线。** 用预期输出和输入条件缩小方法范围，记录实际模型、环境、基线和参数。不会在用户指定的路线失败后悄悄换数据或模型。
4. **先完成适当的小规模检查。** 新环境或新数据先验证一个目标/小批条件的输入、预测和产物，再继续已经约定的范围。
5. **整理完整结果与质量记录。** 先保存原始预测及条件索引，再生成摘要、图和适用的排名。
6. **阅读并交付。** 报告解释本次完成了什么、结果来自什么背景、通过了哪些检查、哪些结论还没有独立支持。

主流程供 Agent 阅读：[SKILL.md](SKILL.md)。详细输入要求：[input-contracts.md](references/input-contracts.md)。运行与失败处理：[execution-playbook.md](references/execution-playbook.md)。

## 先做轻量预检

在本目录执行：

~~~bash
python scripts/preflight.py --help
python scripts/preflight.py --request /absolute/request.json --output /absolute/preflight-001.json
~~~

请求格式和示例见 [预检与排错](docs/troubleshooting.md)。请求内的相对路径按请求文件所在目录解析；输出只新建，重跑时换一个记录文件名。

预检工具检查实际能读取的文件与声明，不安装依赖、不下载权重、不运行模型。CSV/TSV 可以流式检查结构、数值和目标覆盖；H5AD 的检查程度取决于可用读取依赖，并列出未完成的检查。它会分别列出阻断项、警告和未检查项。

**当前实际路线通常返回 `incomplete`，表示仍有必需检查待完成。** H5AD 目前只读元数据和矩阵形状，未扫描表达数值；CSV/TSV 不会自动转换为模型需要的 H5AD；药物表的后端语义仍需核对。`preflight_ready` 即使出现也只覆盖工具声明的有限检查范围，不代表模型环境兼容或已生成预测。正式入口仍需验证权重版本、先验、基因顺序与模型特有输入。缺少资源时报告下一步，保留已经完成的检查。

## 当前能运行到什么程度

| 路线 | 仓库已有内容 | 当前边界 |
| --- | --- | --- |
| CellOracle | 参数化 KO/OE 脚本、输入检查、结果导出及适配测试 | 需要真实 scRNA、匹配 GRN 和独立模型环境；OE 需明确内部尺度设定 |
| Geneformer | 参数化 delete/overexpress 脚本、结果导出及适配测试 | 当前示例面向人类原始全转录组数据与匹配权重；输出 embedding 影响 |
| PRnet、chemCPA、UniPert-G2CP | 肺癌研究的药筛适配脚本、评分与结果契约测试 | 仍需核对和修改历史资源路径，准备匹配环境/权重；先验证小批条件 |
| GEARS、UniCure、DrugReflector | 参考流程、官方资源说明和代码片段 | 需要具体适配与参考复现；尚无通用一键入口 |

这次改进没有重新运行真实模型，也没有用脚本测试替代科学验证。参数化示例、历史复现脚本和文档路线明确分开。环境说明中的历史本机路径不能直接当成你的安装路径。

CellOracle 的表达变化与 Geneformer 的表征影响有不同含义。PRnet/chemCPA 的外部基线需要检查分布与预处理；UniPert-G2CP 当前示例使用模型自带背景。具体限制以对应输入契约和实际版本为准。

## 报告应该怎样读

先读“本次问题与实际输入”，再读以下几类状态，最后看图和候选表：

| 问题 | 看什么 |
| --- | --- |
| 模型有没有生成结果？ | 执行/预测状态：完成、部分完成、失败或不适用 |
| 不同干预的响应能否区分？ | 响应检查；无效、全零或塌缩响应的原因 |
| 预测方向能否解释？ | 疾病参照与评分尺度、逐条件分数、数值容差及方向判定原因 |
| 候选是否有优先级？ | 条件级与药物级排名检查；并列、候选不足和聚合方式 |
| 有独立证据吗？ | 独立验证状态、数据划分/实验来源及未验证范围 |

药物层面汇总后必须再次检查区分度，不能借用剂量条件之间的差异强行排列药物。同分保留并列；全部无法区分时保留诊断值和原因。单个候选可能有可解释的描述性方向，但没有足够候选形成比较排名。

药物恢复方向描述预测转录响应与疾病方向的关系。它不直接确定实际药敏、临床疗效或靶点机制。CellOracle 位移图同样是模型模拟和技术对照，不等于独立实验验证。

结果通常保存在新的运行目录中：

~~~text
results/<run_id>/
  manifest.json
  provenance.json
  validation.json
  errors.jsonl
  raw/
  tables/
  figures/
  report.md
~~~

图表应有对应源表和生成/跳过原因。失败条件保留错误；有效预测不会因为某张图没画出来而消失。药筛同名任务连续或并发启动时也会保存到不同的新目录，避免混写已有结果。

## 开发、验证和打包

Skill 使用和模型运行不是同一个环境安装步骤。仅运行本仓库的快速测试，可以使用独立 Python 3.12 环境：

~~~bash
python -m pip install -r requirements-tests.txt
python -m unittest discover -s tests -v
python scripts/package_skill.py
~~~

测试覆盖输入/结果契约、预检与适配逻辑；部分模型调用使用明确的 mock，不会下载权重或证明预测准确性。打包生成 dist/aivc.zip 并核对逐文件哈希，包含 Skill、必要参考资料、源码和许可；原始数据、环境、权重与运行结果不进入分发包。

Linux 与 Windows CI 对源码测试和打包分别验收。真实模型还需要对应环境中的参考复现和实际产物检查。
