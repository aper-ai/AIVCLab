# 参与 Virtual Cell Research

欢迎从一个清楚的问题开始：增加一个案例、接通一个模型调用、修复一个输入/结果错误，或补齐一段能复现的说明。一次贡献集中于一个问题，方便同行核对来源、运行步骤和证据。

## 增加一个案例

先阅读 [案例目录](cases/README.md) 和 [catalog.json](cases/catalog.json)。案例可以从来源整理开始，不要求首次贡献就下载大数据或运行完整模型。

新增案例至少说明研究问题、来源与版本、数据格式与尺度、干预、对照、所选路线、获取与准备步骤、限制及验收产物。`id` 使用唯一的小写稳定标识；目录字段以 `scripts/cases.py validate` 的要求为准，资源文件名不能包含路径。

为每项资源分别记录 URL、文件名、格式、已知字节数、SHA256、许可状态和条款地址。未知大小、哈希或许可地址可用 `null`，不要写猜测值；模型仓库的代码许可不能自动套用到数据或权重。新案例保留提供方与论文引用，复用代码按 [第三方来源](THIRD_PARTY_NOTICES.md) 登记。

可以增加案例自己的短说明、请求 JSON 和小型准备脚本。命令接收明确输入与新的输出目录，保留稳定样本/基因/条件 ID、单位、处理记录和对照来源。公开数据通过明确资源获取，不把真实数据、模型权重、个人路径、凭据或本地运行目录提交进仓库。合成测试输入必须标为 synthetic fixture，不能进入真实观测案例的证据统计。

### 阶段由证据决定

| 阶段 | 可支持该声明的证据 |
| --- | --- |
| `catalogued` | 来源、问题、资源与限制已收录；不表示数据已取得 |
| `data_downloaded` | 实际文件及获取记录，有字节数和本次哈希；未知预期哈希仍明确未知 |
| `prepared` | 已完成该案例定义的数据准备、观测教学或输入审计，有输入输出身份、命令和检查结果；不表示输入一定适配模型 |
| `model_executed` | 实际模型环境、代码/权重版本、命令、日志、逐条件状态与原生输出；mock 和 `--help` 不计入 |
| `validated` | 明确的独立数据或实验、验证方法、划分与结果；不能用正常退出、内部训练数据比较或来源的 test 标签代替 |

目录中的 `model_status` 和 `validation_status` 必须与阶段一致。教学完成但没运行模型，继续使用 `model_status: not_run`。输入审计正确阻断时，可以按该案例的定义记录 `prepared`，同时明确“案例检查完成/输入契约未通过”；不能把这个阶段解读为输入合格或模型失败。来源方的历史模型结果单独引用，不转写成本项目新运行。

## 增加或修复一条模型适配

优先提交一条明确路线及对应参考输入，说明它接受什么、输出什么、暂不支持什么。例如 TF 网络模拟、token 编码扰动和表达预测的含义不同，不能统一命名后就当作相同结果。

记录具体模型版本、资源来源、环境与硬件条件、预处理、基因顺序、协变量、扰动语义和基线。复用现有输出契约，保存完整原生结果，再计算适用的摘要与图。候选、响应和条件之间按稳定 ID 对应；失败条件、无覆盖目标、未评分原因和独立验证状态分别保存。

为实际改变的行为补有价值的检查，例如基因顺序错位会被拒绝、并列药物不会被强排、缺失输入不会补成零、一个条件失败不会抹掉成功条件。允许用明确的 mock 检查调用/输出适配，但报告必须写明没有加载权重。真实模型执行单独保留可追溯的命令与产物证据。

具体科学边界见 [输入契约](references/input-contracts.md)、[能力登记](references/model-capabilities.md) 和 [下游规范](references/downstream-results.md)。新贡献不需要引入插件平台、通用任务框架或额外智能体内核。

## 本地检查

在独立 Python 3.12 环境、包含 `SKILL.md` 的目录运行。`requirements-tests.txt` 包含数据教学与工程测试需要的依赖，不会安装全部模型环境或下载权重。

```bash
python -m pip install -r requirements-tests.txt
python -m unittest discover -s tests -v
python scripts/cases.py validate
python scripts/cases.py list
python scripts/package_skill.py
```

这些检查验证目录、预检、适配与结果记录，不证明科学预测准确。涉及某个实际模型的变更，应另外说明真实环境中测试到了哪一步，以及未运行的部分。

打包后核对 `dist/virtual-cell-research.zip`：应包含必要文档、源码、案例声明和来源/许可记录，排除真实数据、权重、环境及本地结果。文档中的命令、相对链接和示例参数应与实际代码一致。

## 提交内容怎么写

一个小 PR 应让读者直接回答以下问题：

- **为什么需要这次改动？** 给出具体使用问题或可复现错误。
- **改了什么，结果怎样变化？** 说明输入、操作、输出与解释边界。
- **核实到哪一步？** 列工程测试、真实数据检查、模型执行与独立验证的实际范围。
- **来源和限制是什么？** 给出许可、版本、数据/权重身份以及仍未完成的部分。

如果修正了历史结论，保留旧产物的来源与勘误，重新计算的产物另建目录。不得在缺少原始结果时从图片或 Top 表补造全量响应。
