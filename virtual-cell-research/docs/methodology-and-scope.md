# 方法依据与独立维护范围

Virtual Cell Research 独立维护研究流程、输入与结果契约、案例和质量检查。分析依据来自具体模型的原论文、官方实现、数据提供方记录，以及本项目实际运行得到的证据；历史 Skill 的演示结论不作为本项目新分析成立的前提。

## 哪些内容由本项目负责

| 层次 | 本项目的工作 | 如何核实 |
| --- | --- | --- |
| 产品与流程 | 面向研究任务的入口、首次使用、问题定位、结果阅读和贡献方式 | 主流程、可执行命令、首次使用记录 |
| 工程实现 | 新的数据准备、配对、检查、评估与报告工具；对复用适配代码的维护和修复 | 源码、行为测试、输入输出身份与来源台账 |
| 科学模型 | 按原模型的定义选择资源、预处理和运行方法 | 原论文、官方代码、版本、权重/先验哈希及运行日志 |
| 结果与科学判断 | 说明本次计算了什么、证据支持什么、哪些尚未检验 | 完整结果、对照、指标定义、数据划分和独立验证状态 |

产品独立维护、工程改进和提出新科学理论是不同的声明。本项目可以说明自己新开发或修复的部分；使用 CellOracle、PRnet 等模型时仍引用原模型，不能将其理论和公共数据归为本项目原创。复用代码的来源见 [来源台账](source-ledger.json) 和 [第三方说明](../THIRD_PARTY_NOTICES.md)。

## 每次分析遵守的基本规则

### 先确定比较对象与尺度

观测响应是实际处理值与指定对照值的差。预测响应是模型输出与对应基线的差。两者比较前必须确认基因轴、细胞背景、时间、剂量语义和数值处理一致；不能拿一个模型的归一化预测与另一尺度的原始观测直接算误差。

表达层名、数值范围或文件里的 `test` 标签都不足以独立证明原始计数来源、模型兼容或独立留出。处理步骤记录有效分母、基因筛选、归一化、变换、缺失处理与稳定 ID。出现多基因别名、跨样本重名 barcode 或不确定对照时，先依据原始记录解决对应关系，无法解决的项明确排除或阻断并保留原因。

### 实验单位决定比较方式

供体配对实验以供体为配对单位。单细胞数是每个供体和条件的观测量，不能直接充当独立生物学重复数。按细胞类型形成 pseudobulk 时先保存原始计数汇总与细胞数，再明确归一化与供体内差值；缺失的供体/条件组合不能补造为零。

单细胞来自同一供体，或模型对同一输入重复采样，都不能据此增加独立实验样本数。每种误差条、P 值和置信区间必须有对应的重复单位与统计方法；描述性教学不补造显著性结论。

### 运行、技术质量和预测有效性分别记录

- 下载成功证明取得了特定文件，不能证明文件适用于某模型。
- 预检通过只覆盖所列检查；环境、权重和生物学前提仍需核实。
- 真正加载模型、执行推理或网络模拟并保存输出，才记为模型执行。
- 非有限值、身份错位、退化响应、排名并列分别报告；不能用一个总 `passed` 掩盖失败条件。
- 独立预测验证需要与训练过程关系明确的留出数据或独立实验。官方演示数据与已分发权重的训练重叠不明时，只能记录来源演示/内部参照评估。

测试自己的指标代码与验证科学模型也分别记账：合成 fixture 和 mock 用于工程测试；真实数据检查、真实模型执行和独立评估各有自己的证据。

### 基线不能使用待预测答案

评估至少说明比较了什么简单基线，例如零响应或保持对照表达。若从当前观测集计算均值参照，需要排除待评估药物的全部条件，记录分组与训练范围，并明确它是该数据集内部构建的参照。用全部待测答案求出的均值不能冒充独立预测基线。

先在相同输入、相同基因轴、相同尺度和相同有效条件上比较，再讨论指标差异。高表达背景相关性不能单独证明扰动响应预测准确；无方差、零幅度和无法计算相关系数的情况需要单独记录。

## 模型结果的解释范围

| 路线 | 结果本来的含义 | 本项目报告应保留的边界 |
| --- | --- | --- |
| 观测表达差值 | 数据中处理与指定对照在声明尺度上的差异 | 不自动等于因果效应、药效或预测 |
| CellOracle | 根据拟合的基因调控网络传播 TF 扰动，得到模拟表达变化和状态位移 | 依赖输入背景、先验和网络；投影箭头不是实验追踪轨迹，随机投影是技术对照 |
| PRnet | 依据匹配预处理、基线、药物信息和已训练权重预测转录响应 | 权重与输入域必须匹配；参考数据上的指标不能外推为任意患者药敏 |
| Geneformer | 对 token 编码施加指定操作后得到的 embedding 影响 | 不直接转写成表达倍数或药物疗效 |

CellOracle 的网络模拟方法见 [原论文](https://doi.org/10.1038/s41586-022-05688-9) 与 [官方实现](https://github.com/morris-lab/CellOracle)。PRnet 的预测和留出评估设计见 [原论文](https://doi.org/10.1038/s41467-024-53457-1) 与 [官方实现](https://github.com/Perturbation-Response-Prediction/PRnet)。具体案例必须记录所用版本，不能仅引用论文就声称复现其结果。

## 同行贡献怎样延续这些规则

新增案例或适配可从一项明确问题开始，不要求搭建通用插件框架。提交输入契约、来源、最小运行命令、完整结果位置、检查记录和实际完成阶段。对现有结论的修改保留原始记录与更正依据；遇到不支持的路线，不通过改名、改状态或放松关键检查把它变成成功。

具体步骤见 [贡献指南](../CONTRIBUTING.md)，实际案例与完成阶段见 [案例目录](../cases/README.md)。
