## 先判断入口

| 用户想做什么 | 先做什么 | 不应混淆的事实 |
| --- | --- | --- |
| 了解或复核历史示例 | 打开历史报告、勘误、现存表格和图 | 阅读既有结果不需要安装模型，也不是本次运行 |
| 实际跑一遍参考样例 | 确认样例范围，检查公开输入和匹配资源，生成新运行目录 | 旧样例曾成功不证明当前机器或修正后代码成功 |
| 分析自己的数据 | 继承研究目标，读取已给文件元信息，检查输入契约 | 用户数据不自动替换成示例数据或模型自带对照 |

用户只说“试一下”而没有指向数据或任务时，先简短区分“看已有示例”与“实际运行参考样例”；不要自动发动完整药筛。明确要求运行参考样例时，可按该样例已公开的任务和目标形成默认方案，说明范围，不再要求用户重新填写所有字段。

首次使用的用户说明、命令和提示词见 [first-run.md](first-run.md)。

## 观察、默认设置与一次合并提问

### 先读取已有信息

继承当前任务已明确的文件用途、任务、目标基因/药物、基线、模型与环境。读取文件是否存在、矩阵形状、基因标识、可用层、细胞/样本字段、已有处理记录；检查现有解释器、包版本、权重/先验及硬件条件。记录“用户指定”“从文件核实”“系统默认”三种来源。

只扫描任务相关目录与用户提供的资源，不把历史机器路径当成现有环境。多个表达层、不同用途的数据或互相冲突的处理记录，应列出具体歧义，不能仅依据变量名或整数外观认定 raw counts。

### 可以直接采用的默认

| 设置 | 默认依据 | 必须保留的边界 |
| --- | --- | --- |
| 模型路线 | 研究要的输出、数据类型与实际资源 | 用户已有指定时不替换；表达变化与 embedding 影响不可互换 |
| 解释器 | 项目内已核实的兼容独立环境及匹配版本 | 多个等价环境不必都交给新手选择；版本/权重含义不同则不是等价选项 |
| 工作目录 | 本次项目/工作区中可写的位置，使用新运行 ID | 与原始输入和环境目录分开，不覆盖旧运行 |
| 普通运行参数 | 脚本公开默认、当前样本规模和资源预算 | 改变细胞范围、基因集合、对照或科学解释的参数必须另行说明依据 |
| 出图范围 | 输出类型支持的核心图组 | 用户明确要求的图优先；缺数据的图记录跳过 |

例如，用户明确要 TF 扰动后的表达变化，数据为匹配的 scRNA 原始计数且有 GRN 先验时，可以推荐 CellOracle；若问题是人类细胞表征影响，且完整原始转录组、匹配 checkpoint 与运行条件齐备，可推荐 Geneformer。选择理由简短展示；不要把技术路线自动推断为用户研究结论。

### 只问关键缺项

启动阶段最多一轮简短合并提问。先完成可独立进行的检查，再问会改变任务或结果含义的未知项：

- 目标基因或药物库；多个基因是逐个还是联合。
- 实际分析细胞背景和未干预对照；混合细胞不能凭文件名认定为目标细胞群。
- 无法由处理记录核实的表达尺度、Geneformer 所需完整原始转录组来源。
- CellOracle OE 固定值或分位数及研究依据。
- 仅在疾病方向比较时：疾病参照、对照及差异方向定义。

示例：

> 已找到你给的 `cells.h5ad` 和计数层，并检测到可用 CellOracle 环境。我会把结果保存到本次项目的新目录。还需明确两点：STAT3 和 JUN 是分别扰动还是联合扰动？OE 采用哪个目标值或分位数？CellOracle 的设置值属于模型内部尺度，不是实验表达倍数。

没有缺项时，回显“任务、数据/基线、目标、路线及理由、保存位置”后直接继续。用户补齐后不再追问通用的“确认开始”。后续发现新的阻断证据时，报告具体缺口、已完成检查和下一步，暂停受影响条件，不重开六项问答，也不静默切换模型、基线或目标。

## 检查真实可运行能力

按 [输入契约](input-contracts.md) 检查科学输入，按 [能力登记](model-capabilities.md) 和 [资源与执行入口](model-setup.md) 核对选定后端。只读有关路线，不一次加载全部模型说明。

- **参数化入口**：`examples/ko_oe/celloracle_run.py` 和 `geneformer_route.py` 提供明确 CLI；依然需要真实输入及匹配模型环境。`--help` 成功只证明参数入口可用。
- **历史适配脚本**：PRnet、chemCPA、UniPert-G2CP 的示例包含历史路径与数据假设。先在分析目录保存适配副本，核对当前输入、checkpoint、协变量、基因轴与基线来源，再运行。历史结果不能充当新适配验收。
- **文档研究路线**：GEARS、UniCure、DrugReflector 的 workflow 说明和代码片段是开发/研究参考。资源下载、输入转换、调用与输出都实际完成后，才能登记该路线在当前任务中可用。

复用已核实的兼容环境。需要新环境时，在当前任务已有授权内隔离配置，保留具体版本；实际权限、资源或下载阻碍按事实报告。不要为逃避依赖问题把用户选定模型改成另一个模型。CellOracle 的历史 Windows 适配与依赖说明见 [backend-environments.md](backend-environments.md)，不要照抄其绝对路径。

## 执行与留存

每次使用新目录：

```text
<analysis_dir>/results/<run_id>/
  manifest.json
  provenance.json
  raw/
  tables/
  figures/               # 图与 figure_manifest.csv
  validation.json
  errors.jsonl
  report.md
```

运行记录仍要完整，不把“用户少填表”变成“少保存参数”。至少保存 `data_selection`、`analysis_dir`、`environment`、`task`、`backend`、`intervention` 及各项来源/默认依据；这些是记录字段，不是强制向用户询问的六个问题。另存实际解释器和版本、代码/权重/先验版本与路径、输入用途及哈希、目标逐个/联合方式、药物库版本/范围、随机种子和具体参数。

固定背景模型明确保存实际使用的细胞系和对照；疾病参照另列。脚本没有自动写出的字段由执行者补入记录，并保留原始元数据。不得虚构模型未提供的种子控制或细胞 ID 对应关系。

CellOracle 的模拟表达和 `delta_X` 按内部 log1p(raw-count) 后 KNN 平滑尺度标注。Geneformer `delete`/`overexpress` 分别保存 embedding 影响和官方统计。每个目标或药物条件独立登记；药筛条件需包含稳定药物 ID、剂量、时间、细胞背景和基线来源。以真实文件和索引记录已完成条件，不把目录存在当作 checkpoint 完成证据。

## 结果检查和展示

先保存完整预测、基线、响应、基因轴和条件表，再做筛选、评分或图。复用药筛示例时，先调用 `RunDir.save_predictions`，再执行 `condition_quality`；`top_response_table` 必须按候选 ID 取得对应响应。

分别记录预测是否合法、不同干预的响应差异、评分区分度和独立验证。只完成单个条件时无法进行跨条件差异检查；记录条件不足，不直接判失败。非有限结果、缺失索引或不完整预测阻断相关条件；响应高相关或排名并列触发诊断，不抹去有效原始预测。

按 [downstream-results.md](downstream-results.md) 生成适用图组。每张图先保存源表与参数，再作图并核对文字、轴、色标、图例、条件、单位和对照。图形失败仅重画对应图；缺输入时登记 `skipped`，绘制错误记 `failed`，与模型执行状态分开。

药筛的 `RunDir.finish` 基于完整逐条件数据生成恢复方向清单、`drug_recovery_summary.csv`、`drug_recovery_by_condition.csv`、`drug_top30_genes.csv` 和 `drug_result_rules.json`。仅在疾病评分契约成立时赋予恢复方向；未评分或无效条件保留“无法判定”和原因。仅有原生排名或 embedding 的后端保留其原生结果，不补造逐基因变化。

只读取历史或现有运行时，不自动发动新模型。补图使用已有、完整且可对应的源数据；缺失全量响应不能从旧热图或 Top 表恢复。历史说明和当前勘误并列保留，新检查单独注明时间、规则与输入。

## 失败下一步

| 发现的问题 | 处理当前状态 | 下一步 |
| --- | --- | --- |
| 数据路径、尺度、目标或对照不明确 | 记录输入阻断，不发起相关推理 | 列具体缺项，优先利用处理记录定位 |
| 模型环境/权重缺失或不匹配 | 记录资源阻断 | 修复选定环境或补齐正确资源；不静默换模型 |
| 目标超出后端覆盖 | `no_prediction` | 说明哪一层缺失：输入、tokenizer、GRN 或训练覆盖 |
| 模型报错、无有效输出、NaN/Inf | 对应条件 `failed` | 保存日志、错误阶段与已产出文件，修复后新建运行目录重试 |
| 部分条件成功 | 整体 `partial`，保留逐条件状态 | 只重试失败条件，不覆写已完成产物 |
| 响应难区分或排名并列 | 保留合法预测；排名无法区分记 `unresolved` | 检查基线/预处理/权重、响应与评分口径，停止候选推荐 |
| 缺疾病参照或跨平台尺度不可比 | 跳过疾病方向评分 | 交付模型原生结果并列出需补的比较依据 |
| 只有 embedding 或原生排名 | 标明实际输出类型 | 使用相应图，不生成差异表达或药敏结论 |
| 缺独立实验/留出验证 | `validation_status: unvalidated` | 交付计算结果，说明需要怎样的独立验证 |

错误说明按“发生在哪一步—已核实什么—缺什么—下一步怎么做”组织，避免只抛堆栈。完整堆栈保留在运行记录供排查。

## 交付清单

`report.md` 至少回答：研究问题、入口类型、实际输入和基线、所用模型及版本、完成/跳过/失败条件、主要数值与单位、对应源表和图、技术检查、独立验证、未覆盖项和下一步。

给新用户的阅读顺序是：报告概览 → 清单中的输入/基线/参数 → 分层质量记录 → 主要图与对应表 → 全量原始结果与错误。历史查看、参考样例重跑、用户数据分析分别标注；以本次日志和真实输出为完成依据。
